Overview

The Custom Voice Engine Plugin provides a highly optimized, production-ready voice automation pipeline. It connects directly to your SIP trunks using FreeSWITCH, intercepting audio using mod_audio_fork to stream directly into a Node.js WebSocket backend. The backend orchestrates real-time Speech-to-Text translation, executes system prompts and tool calling via OpenRouter LLMs, synthesizes response text using TTS engines, and streams audio back to the caller.

ℹ
Why use the Custom Voice Engine? Unlike closed-source, full-stack voice API solutions, the Custom Voice Engine plugin gives you complete control over your telephony infrastructure, data retention, billing logic, and AI prompt engineering.

FreeSWITCH & mod_audio_fork Setup

To connect calls to your Custom Voice Engine, FreeSWITCH needs to compile and load the mod_audio_fork module. We provide pre-packaged Docker and Kubernetes deployment files under the plugin's docker/ directory, but you can also install and run it natively on a standard Ubuntu 24.04/Debian VM.

Native VM Installation & Compilation (Ubuntu 24.04 / Debian)

Follow these steps to compile and install FreeSWITCH along with the required mod_audio_fork module:

5. Compile and Enable Audio Format Modules

To play synthesized text-to-speech (TTS) responses back to the caller over ESL, FreeSWITCH requires format modules to read the generated audio files. Build and load mod_sndfile (for WAV format support) and mod_native_file (for raw L16 PCM support):

# Build and install mod_sndfile (WAV file support)
cd ~/freeswitch-build/freeswitch/src/mod/formats/mod_sndfile
make
sudo make install

# Build and install mod_native_file (raw L16 PCM support)
cd ~/freeswitch-build/freeswitch/src/mod/formats/mod_native_file
make
sudo make install

# Enable the modules to auto-load on FreeSWITCH startup:
# Edit /usr/local/freeswitch/conf/autoload_configs/modules.conf.xml and add:
# <load module="mod_sndfile"/>
# <load module="mod_native_file"/>

AWS / Firewall Inbound Rules Configuration

If your FreeSWITCH instance is deployed on AWS EC2 (or another cloud provider behind a firewall/security group), you must configure the following inbound security rules to allow SIP signaling, web console connections, and RTP media traffic:

Type Protocol Port Range Source Description
Custom UDP UDP 5060 0.0.0.0/0 SIP Signaling (Internal Profile / Default SIP Port)
Custom UDP UDP 5080 0.0.0.0/0 SIP Signaling (External Profile / Gateway Trunking)
Custom UDP UDP 16384 - 32768 0.0.0.0/0 RTP Audio/Media Streams (FreeSWITCH media range)
SSH TCP 22 0.0.0.0/0 or Your IP SSH Remote Shell Access
HTTP TCP 80 0.0.0.0/0 HTTP Web Traffic (Optional / Let's Encrypt)
HTTPS TCP 443 0.0.0.0/0 HTTPS Web Traffic / Secure WebSockets
IMPORTANT: Make sure to open the RTP port range 16384-32768 on UDP. If these ports are blocked, your calls will connect but you will hear dead silence (no audio) because the audio packet streams (RTP) cannot traverse the firewall.

Dynamic IP Routing & Variable Broadcast

Because the Node.js server container is assigned a dynamic IP address on every redeploy, the plugin automatically broadcasts its container bridge IP to all online FreeSWITCH nodes via ESL on startup and during health checks. This injects a global variable called ve_audio_ws_url into FreeSWITCH dynamically.

Native Ubuntu Configuration Paths

  • Configuration Directory: /usr/local/freeswitch/etc/freeswitch/
  • SIP Gateways: Place your gateway configurations (e.g. twilio.xml) in /usr/local/freeswitch/etc/freeswitch/sip_profiles/external/.
  • Dialplans: Place your dialplan configuration XML files in /usr/local/freeswitch/etc/freeswitch/dialplan/public/.

Customer Memory System

The customer memory service runs automatically after each call session completes. It generates a summary, determines outcome and sentiment, and extracts new customer facts (preferences, complains, tags) via LLM extraction. These facts are stored in ve_customer_facts and automatically injected into the system prompt of subsequent calls matching the customer's phone number.

Semantic LLM caching

By saving response embeddings in Redis, the engine can match new user transcripts against previously processed answers. If the cosine similarity matches above 0.92, the engine immediately yields the cached response, saving model latency and API costs.

Advanced ESL & Telephony Mechanics

The stability of the bidirectional voice pipeline relies on key protocol improvements that handle low-level event parsing and connection synchronization correctly:

1. Content-Length Based ESL Parser

To avoid packet loss or malformed data under heavy call volume, the Event Socket Library (ESL) interface does not rely on line splits. Instead, it extracts the Content-Length envelope header first, then extracts exactly that number of bytes from the socket buffer to parse the nested headers and payload bodies reliably.

2. Event Subclass Subscriptions

FreeSWITCH expects subclasses to follow the CUSTOM event name explicitly during subscription commands. The plugin establishes two separate event plain commands to avoid subscription failures:

# Subscribing to channel lifecycle events
event plain CHANNEL_CREATE CHANNEL_ANSWER CHANNEL_HANGUP CHANNEL_DESTROY

# Subscribing to custom media stream playbacks
event plain CUSTOM mod_audio_fork::play_audio

3. Connection-Gated Greeting Playbacks

To prevent welcome messages (e.g. firstMessage) from playing to a dead/establishing connection, the session pipeline initialization is deferred until the WebSocket connection from mod_audio_fork is fully established and the audio output callbacks are active. Furthermore, standard binary streams bypass JSON handshakes to prevent FreeSWITCH client protocol errors.

Troubleshooting & Gotchas

Building real-time telephony pipelines involves strict integration rules. Below are the critical troubleshooting lessons learned to resolve common crashes, silence, or audio distortion issues:

1. FreeSWITCH Crash Loops (Segmentation Faults)

Symptom: FreeSWITCH crashes with a segfault core dump immediately when a call is answered or hung up.

Cause: Attempting to destroy mutexes (switch_mutex_destroy) or conditional variables (switch_thread_cond_destroy) that were allocated out of FreeSWITCH's session memory pool after that session is already released and reclaimed.

Fix: Ensure lifecycle release handlers in lws_glue.cpp check !cb->session_released before executing cleanup functions on session variables.

2. ESM Runtime Errors (require is not defined)

Symptom: Node.js server throws ReferenceError: require is not defined in the onAudioOut handler.

Cause: The backend is configured as an ES Module ("type": "module" in package.json). Using inline CommonJS require("fs") calls inside compiled or raw plugin scripts will fail at runtime.

Fix: Use standard ES imports (import fs from "fs";) at the top of the file instead of inline require() statements.

3. Silence on Caller Phone (Leg Selection)

Symptom: Node.js logs show successful broadcast commands, but the caller hears absolute silence on their phone speaker.

Cause: Appending aleg to the broadcast command (uuid_broadcast [uuid] [file] aleg) on a parked channel. Parked channels are single-leg sessions and are not bridged yet, so the audio gets routed to a non-existent leg and discarded.

Fix: Remove the aleg parameter and broadcast directly to the channel: uuid_broadcast [uuid] [file].

4. Invalid File Format Errors

Symptom: FreeSWITCH logs show [ERR] switch_core_file.c:346 Invalid file format [wav] or Invalid file format [raw/l16].

Cause: The FreeSWITCH installation is missing compiled format modules. By default, FreeSWITCH does not have the WAV parser (mod_sndfile) or raw headerless PCM reader (mod_native_file) compiled.

Fix: Navigate to the source folders on the VM and build them: 

# Install WAV Support:
cd ~/freeswitch-build/freeswitch/src/mod/formats/mod_sndfile
make && sudo make install

# Install Raw PCM Support:
cd ~/freeswitch-build/freeswitch/src/mod/formats/mod_native_file
make && sudo make install
Then, load them in FreeSWITCH using load mod_sndfile / load mod_native_file.

5. Metallic Echo / Screeching Distortion

Symptom: The caller hears loud screeching digital static or a distorted metallic echo, but the recording WAV file sounds perfectly clear.

Cause: Byte-order (endianness) mismatch. Standard raw L16 audio is Big-Endian in telephony, but generated Node.js/Deepgram buffers are Little-Endian. Playing Little-Endian files directly as L16 swaps every 16-bit byte, causing static.

Fix: Always use standard .wav files with headers (since WAV headers specify sample rate and Little-Endian format automatically), or perform a buffer.swap16() conversion in Node.js before saving raw L16 streams.
